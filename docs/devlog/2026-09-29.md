and explicit forward/cache/backward implementations for add, whole-tensor reductions, 2D and

transition, pad only incomplete windows, keep the final partial batch, and include epoch in the
seeded shuffle.

## M2.7 — owner training and checkpoint controls; M2 exit

Task: `td-a4fba1`

The Data workbench now owns checkpoint production and selection without requiring Terminal. It
offers only two server-defined presets: a 100-step quick workflow proof and the verified 2,000-step
ready schedule. One training job may run at a time. Its persisted, bounded state exposes step/total,
separate train and validation loss, learning rate, elapsed and estimated remaining time, latest
seeded sample, cancellation state, terminal errors, and the eventual checkpoint id. Cancellation is
cooperative between optimizer/evaluation steps and removes the hidden staging directory without
publishing a checkpoint.

Service restart recovery marks a formerly queued/running/cancelling job `interrupted` and explains
that no partial checkpoint became selectable. Training writes into a dot-prefixed staging directory;
only an atomically completed final directory is moved into the catalog. The catalog rejects path
traversal, ignores staging directories, fully loads and validates every listed checkpoint, hides
corrupt directories, and persists the active id in local generated state. A global sidebar picker
and the Data-page checkpoint cards share one reactive catalog, so either selection updates the
entire app immediately.
