## M2.1 — deterministic math kernels and backward passes

Task: `td-452dcf`

Changed files: A minimal tensor representation backed by `Float32Array`, a serializable seeded RNG,
and explicit forward/cache/backward implementations for add, whole-tensor reductions, 2D and
batched matrix multiplication, last-axis softmax, LayerNorm, tanh-approximation GELU, embedding
lookup/scatter-add, and mean cross-entropy with an optional ignored target.

non-finite values. The RNG preserves its pending Box-Muller value in snapshots. Softmax uses
maximum subtraction, and cross-entropy calculates log-sum-exp directly so a target probability

backward functions are explicitly callable for the transformer gradient checker.

## M2.2 — parameter registry and versioned checkpoint I/O

Task: `td-c4d6d3`

Changed files: The exact default model configuration, authoritative named parameter registry,
checkpoint configuration schema, little-endian Float32 weight encoder/decoder, and Node checkpoint
directory store with validated temporary writes and atomic installation.

Contract implemented: The registry defines all 36 default parameters once and reports exactly
169,728 elements. It supplies fixed ordering, shapes, parameter kind, AdamW decay eligibility,
values, and gradients for initialization, serialization, the future optimizer, and the future
parameter explorer. Seeded initialization uses standard deviation 0.02 for embeddings/matrices,
zeros for linear biases and LayerNorm offsets, and ones for LayerNorm scales. Untied and bias-free

`weights.index.json` as the ordering authority, little-endian `weights.bin`, and the training log.

reloads and validates every artifact, and only then atomically renames it into place.

## M2.3 — one pre-LayerNorm transformer block and checked gradients

Task: `td-91372b`

Changed files: Explicit linear forward/backward kernels, mask-aware stable softmax, scaled
dot-product attention, head split/merge, multi-head Q/K/V/output projections, and a complete
pre-LayerNorm attention-plus-MLP residual block with explicit caches and backward functions.

Contract implemented: Attention uses the configured `1 / sqrt(dHead)` scale. Causal and padding
masks are combined independently for every batch/head; disallowed scores are treated
mathematically as negative infinity without storing non-finite tensor values. A fully padded query
has an all-zero probability row and zero score gradient. The block implements
`x + attention(ln1(x))`, then `x + mlp(ln2(x))`, with separate parameter gradients for every named
registry entry it consumes.

Gradient verification: The tiny checked configuration uses width 4, two heads of width 2, MLP
width 5, three tokens, and a padded final token. An independent test-only Float64 implementation
computes the complete block objective. Central differences use epsilon `1e-4`; every element of all
16 block parameter groups and every input element must have relative error below `1e-3`, with an
absolute-error bound of `2e-5` when both values are near zero. All checks passed.

## M2.4 — full model, optimizer, deterministic batches, and sampling

Task: `td-51a8af`

Pre-task checkpoint: The verified M2.1–M2.3 foundation was committed as `160e8b1`
(`feat: add transformer numerical core and checkpoints`) before this task began.

Changed files: Full language-model forward/backward, vocabulary-by-model unembedding,
cross-entropy integration, tied-gradient accumulation, AdamW with global clipping and decoupled
decay, zero-based warmup/cosine scheduling, deterministic next-token windowing/batching, and seeded
categorical sampling.

Contract implemented: Token and learned-position embeddings feed every configured transformer
block, final LayerNorm, and a vocabulary projection. Tied mode uses the token embedding as the
transposed unembedding and exposes lookup-side and output-side gradients separately before adding
each exactly once. Full backward populates every registry gradient. Untied mode uses its explicit
weight and optional bias.

AdamW computes the global gradient norm in Float64, clips before moment updates, applies bias
correction, and decays only registry entries marked as matrices/embeddings. Schedule indices are
zero-based: with warmup, step 0 is `base / warmupSteps`; the warmup boundary reaches base rate; the
cosine endpoint at `totalSteps - 1` is exactly zero. Deterministic batches divide every document
into non-overlapping prediction windows while retaining the boundary input token needed for each
transition, pad only incomplete windows, keep the final partial batch, and include epoch in the
seeded shuffle.

## M2.5 — tiny-batch learning and target-machine speed gates

Task: `td-e581a8`

Changed files: A reusable deterministic tiny-overfit gate, a locked default training preset,
command-line learning verification, a target-machine default-model benchmark, and unit coverage
that keeps the learning gate in the ordinary test suite.

Learning-rate decision: Fixed-seed 250-step trials used the same one-block width-8 model and the
four transitions `BOS → a → b → c → EOS`. Rate `0.001` selected every correct greedy next token but
reduced loss only 74.15%, below the contractual 80% threshold. Rate `0.003` reduced loss from
`5.5616968658` to `0.0147244789` (99.7353%) and selected `[97, 98, 99, 257]` exactly. Higher tested
rates `0.005` and `0.01` also passed, but `0.003` is the lowest tested passing rate and is now the
default base learning rate. Repeating the full gate with the same seed produced identical metrics.

Ready preset: batch size 8, context 64, 2,000 optimizer steps, 100 warmup steps, base learning rate
0.003, seed `0x5eed`, AdamW 0.9/0.95, epsilon `1e-8`, decay 0.1, and clip norm 1. This processes
1,024,000 target tokens; M2.6 still has to prove falling train and validation loss on real corpus
data before producing the ready checkpoint.

Performance measurement: Apple M4 Max, arm64 Darwin, project-local Node 22.20.0, unchanged default
169,728-parameter model, batch 8, context 64, two warmup steps, and seven measured complete
forward/backward/update steps. Mean forward was 121.70 ms, backward 165.78 ms, update 5.19 ms, and
total 292.67 ms (1,749.42 tokens/second). The slowest measured step was 305.73 ms. A 2,000-step run
projects to 585.34 seconds by the mean and 611.47 seconds using the slowest observed step, both
below the 900-second limit. The profiling/optimization trigger therefore did not fire.
